# MyMozhem

Платформа для приложений-конкурсов (квизы, лотереи, дегустации) на живых и асинхронных событиях. Единый развёртываемый артефакт; ядро даёт общие примитивы (идентичность, комнаты, членство, realtime, реестр приложений), механики — подключаемые app-модули.

**Этап:** MVP (перепроектирование после негодного прототипа v1). Траектория: прототип → **MVP** → платформа → BaaS/SaaS.
**Метод:** AI-Driven / Specification-Driven Development. Спецификация в `docs/` — источник истины и вход для AI-агентов.

Кода пока нет — репозиторий на стадии инициализации. Первая работа (фаза 0) создаёт монорепо-каркас рядом с `docs/`.

## С чего начать (новая сессия)

1. Прочитать `docs/sessions/handoff-to-aidd-session.md` — он задаёт направление.
2. Прочитать `docs/spec/normative-package-v1.2.md` и `docs/roadmap.md`.
3. Начать с открытых вопросов handoff §6, затем строить план перехода / фазу 0.

## Правила репозитория (из нормативного пакета)

- **Источник истины — `docs/spec/`.** Отклонение от ADR — только новым ADR (REQ-DEV-004), до слияния кода.
- **Границы охраняет CI, не соглашение** (ADR-002, REQ-DEV-001): boundary-check обязателен с первого коммита.
- **Не забегать вперёд** (roadmap): не создавать каркасов под отложенные возможности (claim, мультитенантность, второй транспорт). Точка расширения фиксируется словами в ADR, не пустым кодом.
- **Сессионные артефакты AIDD** живут в `docs/sessions/`, не в корне (REQ-DEV-003).
- **Один lockfile** на монорепо (REQ-DEV-002).

## Целевой стек (ADR-006)

NestJS (Fastify-адаптер) · Prisma (PostgreSQL, multiSchema) · zod-контракт в SDK-пакете как единственный источник истины · Socket.io за контрактом ядра · pnpm workspaces + turbo (или nx — развилка фазы 0).
