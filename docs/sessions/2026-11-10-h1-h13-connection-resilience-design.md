# Дизайн фикса находок Н1 + Н13 (устойчивость соединения и сессии)

**Дата:** 2026-11-10 (сессия 56). **Статус:** принят владельцем в brainstorm, перед builder-check.
**Вход:** находки живой приёмки дизайн/UI-среза — Н1 («первый клик молчит», 5 случаев) и Н13 (offline-окно убивает гостевую сессию + auth-шум в логах), протокол — `docs/sessions/2026-10-19-design-ui-acceptance-checklist.md`. Расследование — systematic-debugging, фаза 1 закрыта экспериментом-зондом (`/tmp/mm-click-probe.html`, голая страница без кода проекта).

## §0. Решения владельца (эта сессия)

1. **Затемнение при потере фокуса — чисто визуальное, без щита.** Оверлей не перехватывает клики (никаких `pointer-events` на нём). Обоснование: на macOS ОС съедает клик раньше страницы — щит не при делах; на Windows click-through доставляет клик контенту — щит съедал бы рабочие клики. Визуальное затемнение нигде не мешает, везде объясняет.
2. **Контуры затемнения: play + console. Проектор (screen) исключён** — по нему не кликают, на живом событии он почти всегда не в фокусе, затемнение было бы постоянным и вредным. Участники могут быть и на смартфонах (одно помещение), и на десктопах (распределённое событие) — play-контур покрывается в обоих режимах.
3. **Недошедшая команда — явный отказ, не автоповтор.** Короткое «Отправляю…», затем честная ошибка «не отправлено — проверьте связь, попробуйте ещё раз»; повтор — руками. Очередей команд и авто-дожима нет (надёжнее и проще; двойные отправки исключены конструкцией).
4. **Принцип Н13: сетевой обрыв любой длины НЕ убивает сессию.** Пока лежит сеть — баннер «Нет соединения», клиент retry'ит (backoff + событие `online`), таймер вопроса продолжает идти от серверного `openedAt`. Сессия умирает только при **серверном отказе refresh** (401: кука протухла/отозвана) — тогда автоперезаход новым гостем с честным баннером «вы вошли заново, очки не перенеслись». Законный терминальный случай: офлайн дольше жизни refresh-куки — сервер честно отвечает 401 при возвращении сети.
5. **Проактивный refresh — в объёме.** По пробуждению вкладки (focus/visibilitychange/pageshow — тот же канал, что `wakeUp`): если до expiry access-токена осталось мало — refresh() до того, как запросы пойдут с протухшим. Реактивный путь 401→refresh→retry остаётся страховкой (мейнстрим-паттерн «проактивный сверху, реактивный снизу»: Auth0/MSAL/oidc-client).
6. **Environmentная часть Н1 кодом не лечится, фиксируется документацией.** Подтверждено зондом в Safari, Яндекс.Браузере и Chrome одинаково: когда frontmost — другое приложение, macOS тратит первый клик на активацию окна, странице не достаётся ни одного события (ни pointerdown). Веб-платформа не даёт управления этим (аналог нативного `acceptsFirstMouse` отсутствует). Митигaция — затемнение (п.1): съеденный клик получает видимый смысл.

7. **Расхождение «таймаут сработал, а команда исполнилась» — принимается как есть (решение владельца, builder-check Q4).** Reconciliation-машины (подтягивание состояния перед показом ошибки) НЕ строится. Формулировка честная: «**нет подтверждения** — проверьте, не применилось ли, прежде чем повторять», а не «точно не отправлено». Повторный клик безопасен конструкцией: сервер отвечает конфликтом состояния (409), актуальное состояние сходится через realtime/resync. Авто-дожим по-прежнему отклонён (п.3).

## §1. Что установлено расследованием (корни)

## §2. Цели / не-цели / анти-цели

**Цели:**
- (А) Затемнение нефокусного окна на play + console.
- (Б) Ни одна команда/ответ не теряется молча: publish и REST либо подтверждаются, либо явно отказывают с поверхностью в UI.
- (В) Сетевой обрыв — пауза, а не смерть сессии (принцип решения 4).
- (Г) Проактивный refresh по пробуждению против auth-шума.
- (Д) Документирование environmentного механизма (этот документ + операторская памятка в чеклисте приёмки).

**Не-цели:** изменение серверного warn-логирования 401 (security-сигнал); изменение refresh-ротации и TTL токенов; пере-разметка REQ-* (нормативка не затрагивается — это качество реализации клиента).

**Анти-цели:** очередь команд/авто-дожим (отклонено решением 3); затемнение на проекторе; затемнение при hidden-вкладке (мобильный app-switch — страница не видима, затемнять нечего); перехват кликов щитом (решение 1); нативные обёртки/PWA.

## §3. Дизайн по частям

### (А) Затемнение нефокусного окна — play + console

- **Триггер постановки:** `window` получил `blur` **и** `document.visibilityState === 'visible'`. Условие «visible» — ключевое: оно отделяет десктопный сценарий «окно видно, но фокус в другом приложении» от мобильного app-switch (там страница становится hidden — затемнения нет, ложных срабатываний на смартфонах нет).
- **Снятие:** `focus` на `window`.
- **Форма:** полноэкранный визуальный слой (затемнение + короткий текст-пояснение), **без** `pointer-events` — клики проходят сквозь него (решение 1). Уважает reduced-motion (никаких анимаций появления при RM; существующий RM-блок стилей — прецедент).
- **Стили:** токены/каскад по идиоме дизайн-среза (`styles/`, per-контурные файлы; новые литералы — кандидаты в токены с комментарием).
- **Взаимодействие с ConnectionBanner:** независимы. Затемнение — про фокус окна, баннер — про состояние соединения; могут сосуществовать.

### (Б) Явный отказ недошедшей команды

**Socket-путь (`RoomConnection.publish`):**
- Ack-таймаут: socket.io-client 4.8.3 поддерживает `socket.timeout(ms).emitWithAck` — промис reject'ится по таймауту. Завернуть в `SocketLike` (граница `realtime/` сохраняется, REQ-RT-006-зеркало).
- Fail-fast: если сокет заведомо не connected (`isConnected() === false`) — немедленный отказ, не ждём таймаут.
- Оба случая наружу — типизированный `ApiError` с различимыми кодами (например, `NOT_CONNECTED` / `PUBLISH_TIMEOUT`), статус 0 по прецеденту wire-уровня.

**REST-путь (`ApiClient` + `SessionStore.refresh`):**
- fetch с `AbortController`-таймаутом (применяется и к основному запросу, и к refresh-вызову): подвисший single-flight больше не может висеть вечно — мемо сбрасывается по settle (уже есть), settle теперь гарантирован таймаутом.
- Таймаут = сетевой класс отказа (см. классификацию в (В)), не путать с серверным отказом.

**Поверхность в UI (решение 3 + builder-check Q2/Q4):**
- Каждая сетеватая кнопка (ответ участника на play; команды ведущего на console — open/close/reveal/finish, complete/cancel, exclude, draw, fulfill/revoke) получает состояние «Отправляю…» на время полёта и, при отказе, — явное сообщение рядом с контролом + кнопка остаётся доступной для повтора.
- Setup-экран организатора (место первого случая Н1 — configure) уже имеет поверхность ошибок (`submitError`, `role="alert"`, маппинг кодов): таймаут ApiClient механически убирает вечное зависание, отказ показывает существующая поверхность; недостающее busy-состояние — по §4.
- Формулировка отказа — честная (решение 7): «нет подтверждения — проверьте, не применилось ли», не «точно не отправлено».
- Состояние занятости локально для действия; глобальный спиннер не нужен. ConnectionBanner/индикатор консоли продолжают жить своей жизнью.

### (В) Сессионная машина: сеть ≠ отказ сервера (Н13)

- **Классификация отказов** в одном месте. Таблица (уточнена по builder-check Q1):
  - **Терминальный класс — ровно один:** `ApiError` со статусом 401 (SESSION_INVALID) на refresh — сервер по существу отклонил refresh-куку (протухла/отозвана/кража семьи).
  - **Временный класс — всё остальное:** `TypeError` fetch (сеть лежит), AbortError/таймаут, а также `ApiError` 5xx/`HTTP_5xx` и не-JSON ответы прокси. Кейс builder-check: рестарт/редеплой сервера посреди живого события даёт 502 от прокси на refresh — это инфраструктурный обрыв, сервер сессию не судил; отнесение 5xx к терминальным убивало бы все гостевые сессии разом при каждом рестарте (прямое нарушение решения 4).
- **`RoomConnection` (connect_error → refresh):** серверный отказ refresh → терминальный путь как сейчас (`onSessionDead` → автоперезаход). Временный отказ → НЕ терминальный: состояние 'disconnected', повтор refresh при `online`/пробуждении; сокет продолжает свои retry (backoff живой, skipReconnect=false — транспортный обрыв лечит сам socket.io).
- **`rejoinAsGuest` (play):** временный провал rejoin — НЕ `clearGuest`: остаёмся на баннере «Нет соединения», повтор по `online`. Терминальный clearGuest — только на серверном отказе (комната терминальна, join отклонён).
- **Итог:** разрыв сети и инфраструктурные 5xx любой длины = пауза; смерть сессии — только по слову сервера (решение 4).

### (Г) Проактивный refresh по пробуждению

- На focus/visibilitychange(visible)/pageshow: если access-токена нет или до его `exp` осталось меньше порога — `SessionStore.refresh()` (single-flight уже дедупит конкурентов).
- **Точка монтирования (уточнено по builder-check Q3):** НЕ внутри `useRoomBinding` (там живут только room-страницы), а на каждой странице, владеющей сессией: host включая setup-экран (место Н1-случая с configure), play, **screen** (экран тоже держит сессию и даёт свои `socket auth failed` строки шума). Канал пробуждения — тот же дедуп `createFocusRefetcher`.
- Порядок относительно `wakeUp`-кика на room-страницах: сначала refresh, потом кик reconnect — handshake уйдёт со свежим токеном.
- Порог и декод `exp` — расширение `decodeAccessClaims` (сейчас exp не читается).
- Эффект: первые запросы после простоя идут уже со свежим токеном → 401-цыпочки и warn-шум почти исчезают; реактивный 401-путь остаётся страховкой.

### (Д) Документация environmentного механизма

- Этот документ — первичная фиксация (решение 6 + таблица §1).
- В операторскую памятку/чеклист приёмки добавить строку: «первый клик по окну при frontmost вне браузера тратится на активацию — это macOS, не дефект; затемнение показывает состояние» (файл — по решению при планировании, кандидат: раздел наблюдений чеклиста приёмки).

## §4. Оставлено строителю (мои звонки, не решения владельца)

- Точные таймауты: publish ack ~5 с; REST/refresh ~10 с (на живом событии секунды дороги, но LAN/слабая сеть требует запаса; значения — константы с комментариями).
- Порог «мало до expiry» ~2 мин при TTL 15 мин.
- Тексты: затемнение («Окно неактивно — кликните, чтобы продолжить» / аналог), отказы («Не отправлено — нет связи. Попробуйте ещё раз»). Финальная редакция — на живой приёмке.
- Точная форма состояния «Отправляю…» (disabled + текст кнопки vs спиннер рядом) — по месту, в идиоме среза.
- Механика повтора refresh по `online`: слушатель `window.online` + немедленный retry; backoff сокета не трогаем.
