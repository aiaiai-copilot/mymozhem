## 0. Решения владельца (сессия 16, 2026-09-23)

Приняты в ходе brainstorm, дальнейшей перелитігации не подлежат (пересмотр — только новым основанием через ADR-процесс, REQ-DEV-004):

1. **Объём среза:** полный цикл первого события — квиз + лотерея + rewards (организатор: логин, комната, редактор квиза, ведение, призы, розыгрыш, fulfill/revoke, исключение; участник: join, ответы, табло; экран-проектор). Не curl-заглушки.
2. **Участники — только гости** (код комнаты + displayName). Backend-контур join не меняется (JoinController остаётся GUEST-only). Этим закрыт открытый вопрос D-12.1 (registered-join шов): в MVP registered играют как гости; шов — задел до продуктового требования.
3. **Топология:** один SPA `apps/web` (Vite + React + TS), прод — статика раздаётся Fastify из того же Docker-артефакта (same-origin). Этим потреблён follow-up «CORS/credentials»: CORS не включается вообще, refresh-кука `SameSite=Strict` работает без изменений.
4. **Дизайн — функциональный минимум:** чистая вёрстка без дизайн-системы, mobile-first для участника. Дизайн-проход — отдельный срез после первого события.
5. **Редактор квиза — форма в UI** (не JSON-paste).
6. **Проекторный экран нужен** (spectator-view, роль SPECTATOR уже есть в backend).
7. **Подход A — клиентский слой внутри `apps/web`, проекции через переиспользование чистых редьюсеров app-пакетов.** **Зафиксировано как временное решение MVP.** Точка расширения (словами, не кодом, CLAUDE.md §2.3): выделение framework-agnostic `@mymozhem/client-sdk` — задел платформенной фазы при появлении внешнего потребителя; клиентский слой проектируется без React-зависимостей вне хуков, чтобы выделение было механическим.
8. **Браузерный e2e — Playwright smoke-сьют** (happy-path), в CI.

## 1. Цель и критерии успеха

Провести первое живое событие целиком через UI, без единого ручного REST-вызова: организатор создаёт комнату, наполняет квиз, ведёт его на экране, разыгрывает призы и закрывает вручение; участники играют с телефонов по ссылке; вопрос и табло видны на проекторе.

Критерии приёмки среза — §8.

## 2. Топология, пакет, сборка

- **Пакет `apps/web`** (workspace, не публикуется): Vite + React 18 + TS strict. Зависимости: `@mymozhem/sdk` (типы + zod-схемы), `@mymozhem/app-quiz`, `@mymozhem/app-lottery` (только редьюсеры/типы/схемы), `socket.io-client`, `react-router`. Без state-фреймворка: состояние комнаты — один reducer на подписку (§3).
- **Boundary (depcruise, новые правила + probe в guardrails):**
  - `apps/web` → только `@mymozhem/sdk`, `@mymozhem/app-*`; `@mymozhem/core` запрещён;
  - `socket.io-client` — только внутри `apps/web/src/realtime/` (зеркало серверного правила REQ-RT-006).
- **Прод:** `vite build` → статика в Docker-артефакте; Fastify раздаёт same-origin (`@fastify/static`, SPA-fallback на `index.html` для не-API маршрутов; API-пути регистрируются до static). CORS не включается.
- **Dev:** vite dev-server с proxy REST-путей backend'а (`/rooms`, `/auth`, `/health`) и `/socket.io` (ws) на локальный server; для браузера всё same-origin, CORS не нужен и в dev.
- **CI/сборка:** turbo-таски `build`/`lint`/`typecheck`/`test` для web (build зависит от build sdk/app-*); Dockerfile += стейдж сборки web, dist копируется в runtime-стейдж рядом с server dist.

**Pre-tasks среза (решения сессии 16 по вопросам ф.3, код до клиентских задач):**
- **P1 (C-9.1, REQ-RWD-014):** `toRegisteredSchema` в SDK генерирует JSON Schema в input-режиме (`io: 'input'`) — defaulted ключи appSettings необязательны в артефакте, configure `{}` проходит verdict-only гейт, дефолты применяет zod-parse handler'а. SDK → 1.7.0. Контрактные тесты: defaulted ключ необязателен; `{}` принимается.
- **P2 (drawPool):** `MembershipService.listActiveParticipantPool` += фильтр `identity: { deletedAt: null }` (свипнутый гость вне пула розыгрыша) + тест.

## 3. Клиентский слой данных и проекции

Wire-событие — `{type, payload, actorId}` (`projectedEventSchema`), без id/seq: дедупликация на клиенте структурно невозможна (REQ-RT-011a, принятый риск realtime-дизайна §4 — duplicate-acceptance в subscribe). Отсюда стратегия:

- **`src/api/`** — typed REST-клиент: fetch-обёртка, zod-валидация ответов схемами SDK (fail-loud при дрейфе), `ApiError` по `CONTRACT_ERROR_CODES`. На 401 — один silent `POST /auth/refresh` + один retry; дальше — состояние «сессия протухла» (гость → повторный join по сохранённому коду; организатор → OAuth-вход).
- **`src/realtime/`** — единственный импортёр `socket.io-client`. `connectRoom(roomId)`: handshake с access-токеном; `subscribe` → ack со snapshot (полная видимая проекция лога, курсора нет) + live-поток; встроенный reconnect → автоматический re-subscribe.
- **`src/state/`** — фолд событий: live буферизуются до snapshot; snapshot фолдится **с нуля** через редьюсер app-пакета (`reduceQuiz` / редьюсер лотереи из `@mymozhem/app-*`); затем применяется буфер. Дупликат из окна handshake возможен и принят (лечится переподключением — полный перефолд); **потеря** события исключена структурно. Поверх — селекторы: текущий вопрос, табло, мои ответы, состояние розыгрыша.
- **Публичные appSettings** (вопросы, scoring) приезжают в логе как public-проекция; module-private (`correctAnswers`) клиент структурно не получает (REQ-CORE-008) и не запрашивает.

## 4. Маршруты и флоу по ролям

- `/` — лендинг: «Я организатор» (→ OAuth Google) / «У меня есть код».
- `/host/*` — организатор (registered-сессия, иначе редирект на `/`). Флоу линейный, комната одна (id в localStorage; списка комнат в API нет и не нужен):
  1. OAuth → `POST /rooms`.
  2. **Редактор квиза** (форма: вопросы/варианты/правильный/scoring/minAnswerIntervalMs) → `configure` (quiz@2) → `activate`.
  3. **Консоль ведущего:** код комнаты крупно + копируемая ссылка; ведение — «открыть вопрос N» → счётчик ответов live → «закрыть» → «показать ответ» → табло; список участников с исключением (exclude); призы (создание + quantity, список awards); «разыграть» (draw.run) → победитель; fulfill/revoke; завершение комнаты.
- `/play/:code?` — участник: код из URL/ввод + displayName → guest-join → лобби → вопрос с вариантами → ack «принято» → после reveal «верно/неверно» + табло → финал: итоговое табло + победители розыгрыша.
- `/screen/:code` — проектор: spectator-join по коду, read-only: текущий вопрос крупно → табло после reveal → итоги лотереи.

**Явно вне объёма:** QR-код ссылки (копируемая ссылка + крупный код достаточно), список комнат организатора, registered-участники, дизайн-система, error-tracking сервис.

## 5. Ошибки и переподключение

- **Обрыв соединения:** reconnect → re-subscribe → свежий snapshot → полный перефолд (самолечение). Во время обрыва — явный индикатор «нет соединения» у участника и ведущего.
- **Сессия гостя протухла** (refresh TTL): повторный join создаёт **новую** identity — очки старой не переносятся. Принято для MVP; UI честно показывает «сессия истекла, вы вошли заново». Перенос identity — задел.
- **REST-ошибки:** типизированные коды → UX-маппинг (`ROOM_NOT_FOUND` → «проверьте код», rate-limit → «подождите», validation → подсветка поля); неизвестный код → общий экран с «обновите».
- **zod fail-loud** на границах (REST-ответ, wire-событие) → общий экран ошибки в проде.
- **Организатор:** протухшая сессия → повторный OAuth, комната из localStorage.

## 6. Тестирование

- **Unit (vitest):** буфер/перефолд event-log (кейсы «live до snapshot», дуп-окно handshake, reconnect-перефолд), селекторы, REST-клиент (mock fetch: 401→refresh→retry, маппинг кодов). Редьюсеры app-пакетов уже покрыты — не дублируем.
- **Golden-фикстура:** записанный лог квиз-событий, фолд клиентом ≡ ожидаемая проекция (страховка порядка/буфера, не редьюсера).
- **Playwright smoke (в CI):** happy-path — участник join → ответ → табло; организатор create → configure → activate → open/close/reveal. Против docker-compose стенда. НЕ против production (глобальное правило тестирования).
- **Ручной smoke-чеклист** перед первым событием (покрывает и OAuth smoke с реальными Google-кредами — действие владельца).

## 7. Границы и гейты CI

- Новые depcruise-правила (§2) + probe в guardrails; существующие гейты не ослабляются.
- turbo-пайплайн += web (build/lint/typecheck/test); e2e Playwright отдельной таской (docker-compose стенд).
- Dockerfile: стейдж сборки web; runtime-стейдж += web dist; поведение server не меняется (порядок маршрутов: API → static → SPA-fallback).
- Один lockfile (REQ-DEV-002) — новые зависимости только через него.

## 8. Критерии приёмки среза

1. Первое событие проводится целиком через UI: create → editor → configure/activate → ведение квиза → призы → розыгрыш → fulfill/revoke → завершение; ни одного ручного REST-вызова.
2. Участник с телефона: join по ссылке → ответы → табло; обрыв соединения виден и самолечится переподключением без потери состояния (перефолд).
3. Проекторный экран: spectator-view показывает вопрос/табло/итоги без интерактива и без auth-контура.
4. `correctAnswers` недоступны ни на одном клиенте (структурно — replay/видимость; наследует чит-тест ф.2).
5. Pre-tasks P1/P2 исполнены: configure `{}` с defaulted полем принимается (контрактный тест SDK 1.7.0); свипнутый гость вне drawPool (тест).
6. Конвейер зелёный: существующие гейты + web build/lint/typecheck/unit + Playwright smoke + новые boundary-правила с живыми probe'ами.

## 9. Риски и задел (фиксируются, не решаются в срезе)

- **Duplicate-acceptance** на клиенте — принято (wire без id/seq); самолечение переподключением. Закрытие — seq/cursor, ф.4 (REQ-RT-011б).
- **Перенос гостевой identity** при протухшей сессии — задел (продуктовое требование отсутствует).
- **Выделение `@mymozhem/client-sdk`** — платформенная фаза (решение №7, §0).
- **QR-код, список комнат, дизайн-проход, error-tracking** — отдельные срезы после первого события.
- **Registered-join шов (D-12.1)** — закрыт решением №2 (§0): гости-only; шов — задел до требования.
