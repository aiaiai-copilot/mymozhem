**Критерий прохождения:** `curl -s http://localhost:3000/health/live` → 200; лендинг открывается в браузере.
**Протокол:** ✅ 2026-10-21 · compose из worktree (`design-ui-slice-server-1`, PRIZE_MODE=on, COOKIE_SECURE=false) · health 200, лендинг отдаётся с `data-theme="rybinsk"` · Наблюдение Н6: лендинг не стилизован (вне объёма среза — дизайн-док его не упоминает; триаж владельца в конце прогона).

### 0.2. LAN-вариант для телефонов

Телефоны ходят на `http://<ip-машины>` в общей Wi-Fi сети. Два допустимых подъёма:

- **Bare-run (норма события, образец — §0.4 smoke-чеклиста):** в контейнере только БД (`docker compose up postgres`), сервер на хосте: `pnpm build` из корня, затем `DATABASE_URL=postgresql://mymozhem:mymozhem@localhost:5432/mymozhem JWT_SECRET=... ORGANIZER_SETUP_TOKEN=... PRIZE_MODE=off COOKIE_SECURE=false WEB_STATIC_DIR=<корень репозитория>/apps/web/dist pnpm --filter @mymozhem/server start`. `WEB_STATIC_DIR` — хостовый путь к собранному SPA, т. е. после `pnpm build` (compose задаёт контейнерный `/app/apps/web/dist`; без переменной сервер статику не отдаёт — `static-web.ts` выходит рано). **ВНИМАНИЕ: compose по умолчанию НЕ публикует порт 5432 на хост** — для bare-run добавить `docker-compose.override.yml` с пробросом 5432 (см. комментарий в `docker-compose.yml`). Web отдаётся тем же сервером (WEB_STATIC_DIR) — один origin на LAN-IP.
- **Compose + публикация портов** — допустим для UI-приёмки (docker NAT скрывает реальные IP, но эта приёмка не тестирует exclusion/rate-limit; блокеры репетиции здесь не кусаются).

**COOKIE_SECURE=false — ТОЛЬКИ для plain-HTTP LAN** (иначе телефоны не примут refresh-куку и сессия будет с 15-минутным потолком).
**Известное ограничение LAN:** розыгрыш по `http://<ip>` недоступен (`crypto.randomUUID` — secure-context-only): блок 10 (финал с розыгрышем) прогонять консолью с `localhost` машины стенда, сцены при этом могут оставаться на LAN-устройствах.

**Критерий прохождения:** телефон открывает `http://<ip>:3000`, лендинг рендерится; участник с телефона заходит в комнату (join не отклонён, сессия живёт дольше 15 мин при COOKIE_SECURE=false).
**Протокол:** ✅ 2026-10-21 · iPhone Safari → `http://192.168.0.104:3000/play/...` · join принят, участник играл весь квиз (4 вопроса + финал, ~1,5 ч сессии) · compose-вариант; `joinIp` в БД = docker NAT gateway — известное ограничение, допустимо по строке.

### 0.5. Раздельные браузеры/профили

Refresh-кука одна на origin (`mm_refresh`): вход организатора затирает гостевую куку участника и наоборот. Консоль и тест-игрок с одного десктопа — разные браузеры/профили/инкогнито; телефоны — отдельные устройства.

**Критерий прохождения:** после входа организатора вкладка участника в другом браузере продолжает получать события; «внезапных разлогинов» внутри одного профиля не интерпретируем как баг.
**Протокол:** ✅ 2026-10-21 · раскладка: Safari — консоль, Chrome — проектор, Яндекс — участник Петя (всё макмини), iPhone Safari — участник Александр · разлогинов не было; дубли «Экран (зритель)» при повторном открытии /screen — прежняя известная семантика join (Н7, не находка среза).

## 2. Компонентные состояния (дизайн §8, п. 15)

### 2.1. hover/active — мышь

Консоль и редактор на ноутбуке: наводить и нажимать кнопки всех видов (primary, secondary, quiet) и варианты ответов на сцене (участник с десктопа).

**Протокол:** ✅ 2026-10-29 · Safari/Chrome, консоль + редактор + сцена · hover — мягкая смена заливки у всех видов кнопок, active — мгновенно и глубже; кнопки без рамок, включая тихие · находка **Н15**: у консольного toggle «ещё N — развернуть» hover-отклика не было (только cursor:pointer) → **починено в срезе** (`203cb78`: `:hover` под `@media (hover:hover) and (pointer:fine)` + страж в tokens.spec, проверено живьём).

### 2.2. focus-visible — клавиатура

Пройти консоль и форму входа участника табом (Tab/Shift+Tab, Enter/Space на кнопках и radio).

**Критерий прохождения:** контур фокуса 3px с offset 2px виден ТОЛЬКО при клавиатурной навигации (консоль — `#10514F`, сцена — золото `#E6C77D`); клик мышью контур не оставляет; вся консоль управляема с клавиатуры (включая radio-группу редактора и toggle «ещё N — развернуть»).
**Протокол:** ✅ 2026-10-29 · Safari, консоль + редактор + форма входа · контур 3px с offset виден ТОЛЬКО при клавиатуре; клик мышью контура не оставляет; toggle «ещё N» активируется с клавиатуры (Enter) · платформенные конвенции Safari/macOS (подтверждены экспериментально, НЕ дефекты): полный обход — **Option+Tab** (дефолтный Tab ходит только по текстовым полям); клик мышью не даёт клавиатурный фокус radio/кнопкам — стрелки по radio-группе работают после Option+Tab (закрывает клавиатурный хвост 15.2: «да так, теперь выбор ходит»).

### 2.3. Тач на телефоне — без липкого hover

На телефоне (тач): нажатия на кнопки и варианты.

**Критерий прохождения:** hover-подсветка не «залипает» после тапа (hover только при `@media (hover:hover) and (pointer:fine)`); active-нажатие видимо (глубокая заливка) в момент касания.
**Протокол:** ✅ 2026-10-29 · iPhone Safari (тач) · active-заливка видна при прижимании с удержанием; быстрый тап переключает; липкого hover после тапа нет (hover объявлен только под `@media (hover:hover) and (pointer:fine)` — на таче структурно недостижим) · долгое удержание (long-press) кнопку НЕ переключает — платформенная конвенция iOS (click гасится), не дефект.

Включить «уменьшение движения» в ОС/браузере (macOS: Системные настройки → Универсальный доступ → Дисплей → Уменьшить движение; или эмуляция в DevTools → Rendering → prefers-reduced-motion), затем reveal с приростом очков.

**Критерий прохождения:** анимация доезда дорожек (var(--t-race)) отключена — полосы появляются мгновенно; hover-переходы погашены; **таймер продолжает тикать** (таймер — контент, не анимация, п. 15).

- Прогон — владельцем (или с владельцем) на реальных устройствах: минимум один телефон-участник, консоль на телефоне и ноутбуке, проектор/второй экран. Стенд — локальный/LAN, НЕ production.

- Находки за пределами критериев §12 не блокируют мердж сами по себе — триаж владельцем по образцу deferred-триажа батчей; блокируют только провалы строк, закрывающих критерии таблицы §12.
- После прогона: заполненный чеклист коммитится в `docs/sessions/` этим же файлом (строки ⬜ → ✅/❌); финревью батча E и мердж среза — после зелёной приёмки.
