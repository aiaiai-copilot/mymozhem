### Решения владельца этой сессии (rationale — чтобы не переоткрывать)

- **Тест конкурентности: `cancel` + `cancel` вместо предписанного планом `activate` + `cancel`.** План был schedule-dependent: при сериализации проигравшая операция читает `ACTIVE`, а `ACTIVE → CANCELLED` легален — оба промиса резолвятся, и тест падает без всякого дефекта. Замена даёт ровно одного победителя при любом расписании. Сопутствующее утверждение плана «intermittent failure = не атомарно = реальный дефект» ошибочно и в код не перенесено.
- **Soft-delete guard выводится из `DELETABLE_STATUSES`** (§3 дизайна главнее §4).
- **CHECK-инвариант soft-delete добавлен в БД** — правило переехало из кода сервиса в схему, с тестами через raw SQL (сервис по построению не может создать нарушающую запись).
- **Ветка не публиковалась** — шаг 4 Task 7 (`git push`) пропущен. Решение принято на основании устаревшей записи леджера, которую я привёл как факт, не проверив; фактических препятствий к публикации не было. Решение владелец подтвердил и после исправления.
